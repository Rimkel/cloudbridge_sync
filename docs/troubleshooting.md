# 故障排查

- **提示未找到 rclone**：安装官方 rclone，或配置 `backend.executable` 为绝对路径。后台服务 PATH 可能与终端不同。
- **remote 不存在**：在运行服务的同一用户下执行 `rclone config`，确认 `RCLONE_CONFIG` 与权限。不要输出或提交配置文件内容。
- **重启 OpenList 后存储消失、又要求初始化**：先确认启动工作目录。默认配置和数据库位于启动目录下的 `data`，在别的目录运行可能创建另一套空数据并导致原 rclone 密码失效。保留所有数据目录，查找原 `data.db`，停止错误实例后用原目录及绝对 `--data` / `--config` 路径启动。不要先重置密码、重新授权或删除数据库。Windows 可用 `scripts/start_windows_openlist.ps1 -DataDirectory '原 data 目录'`，它会检查已有默认 SQLite 文件再启动。
- **认证失效 / 权限不足**：重新检查 OpenList 用户权限和百度授权。认证错误按永久失败处理；修复后重启，并对停止的文件执行 `--force --once`。
- **第一轮未上传 / 下载**：首次观察必须等下一轮。上传还需满足最小文件年龄及大小、修改时间不变。`--once` 只执行一轮，不在内部等待第二轮。
- **临时网络错误**：查看 `status` / `logs`。按 `retry_base_seconds * 2^(attempts-1)` 退避并封顶；总尝试次数受 `retry_attempts` 限制。常驻扫描间隔也会影响实际重试时间。重启保留退避与尝试次数，未完成传输恢复为 `RETRY`。
- **失败任务达到尝试上限**：停止同步后执行 `cloudbridge --config configs/windows.yaml retry-failed --mapping 映射名`，再正常启动；只恢复临时失败，不重传成功任务。永久失败和本地冲突需要分别解决，不能靠重启清除。
- **Windows 新文件很久才出现**：检查本机 OpenList 存储的目录缓存，以及日志中的列目录和整轮耗时；`interval_seconds` 并非从一轮开始到下一轮开始的固定间隔。更新后的下载器快速跳过未变化的成功文件，避免每轮重读整个历史目录。
- **冲突未下载**：默认 `skip` 保护未知或被本地修改的同名文件。`--force` 不绕过保护。人工比对后移动文件或显式配置 `overwrite`。
- **同大小的云端变更未发现**：WebDAV 元数据不足时不可可靠判断，使用 `download --force --once` 并进行本地 SHA-256 对照。不要以 `--size-only` 证明内容一致。
- **远端大小验证失败**：网关缓存、上传延迟或文件正在变化均可能导致失败；等待下一轮重试。不要直接将状态改为成功。
- **已有实例占用**：停止重复进程。锁文件存在本身不代表锁有效；进程退出后操作系统释放锁，无需删除锁文件。
- **配置重载失败**：完整校验后原配置继续工作。方向、remote、云端根目录或状态库变化要求重启及独立状态库。命令行修改 YAML 使用原子写入。
- **路径拒绝**：避免重叠映射、`..`、远端绝对映射、符号链接、Windows 保留文件名或大小写冲突。同一相对路径结构会保留，不自动重命名有歧义的文件。
- **Windows 文件占用**：关闭占用该文件的应用后重试，查看日志中的 `PermissionError`。本项目尚未在真实 Windows 验证此场景。
- **遗留 `.cloudbridge-*.part`**：异常断电可能留下暂存文件，它们不会成为成功目标或被上传。确认无进程使用后由用户人工处理，应用不扫描删除历史文件。

默认日志只记录分类后的 rclone 错误和退出码，不打印原始 stderr，避免泄漏 URL 或令牌。配置错误会显示字段位置，分享日志前仍应自行检查私有路径和账号信息。

后端错误已细分 HTTP 401（登录认证）、HTTP 403（请求被拒绝）和可识别的百度授权错误，并标明失败发生在元数据查询、目录读取或递归扫描。只有数字 401/403 出现在文件名或请求 ID 中时，不会据此判为永久认证失败。旧 Windows 安装包需要更新对应 Python 代码才能显示这些新提示；仅凭旧版的“认证失效或权限不足”不能确定根因。
